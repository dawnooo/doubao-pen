# 后台调用

使用前确认当前机器已安装 OpenCLI。使用它的豆包网页版适配器 `opencli doubao`，与桌面版适配器 `doubao-app` 区分。前置条件是可用的 Chrome Browser Bridge 连接和豆包页面会话；CLI 后台驱动页面，不占用桌面鼠标键盘，仍需 Chrome 和扩展运行。

先查看本机实际帮助，避免按过期参数调用。帮助命令不访问豆包页面，可在加锁前执行：

```powershell
opencli doubao --help -f yaml
```

`Status=Connected` 只说明页面可达；`Login=Unknown` 不能证明已登录或已能生成。以实际收到完整答复为准。登录、验证码或权限门禁交用户处理，保持后台调用，不自行转用桌面控制或更改浏览器安全设置。

## 跨对话串行锁

使用 Node.js 20 或更新版本运行本 skill 的 `scripts/session-lock.mjs`。先解析当前 skill 的绝对路径，以下 `$lock` 指向该脚本；不要依赖当前工作目录。各 Codex 对话、各份 skill 安装共用当前 OS 用户的 `~/.codex/locks/doubao-pen`，避免各自新建锁目录导致隔离失效。这个锁保守地串行所有豆包浏览器配置，不是分布式锁，也不能拦截其他程序直接调用 OpenCLI。

```powershell
$lock = '当前skill绝对路径/scripts/session-lock.mjs'
node $lock acquire --owner '当前对话或任务的唯一标识'
```

成功返回 JSON 中的 `token`，将其保存在当前任务上下文，需要跨 shell 调用时从该上下文恢复。`status` 不会披露 token，其他任务不得读取或借用持有者的 token。退出码75表示被占用：先做独立工作或等约30—60秒，再尝试 `acquire`；不高频抢锁，也不执行任何豆包页面操作。等待用户登录等交互过程也属于该稿件会话，保留锁。

独立任务在成功持锁后新建对话；修订沿用原会话。`run` 支持 `new`、`send --text-file`（可加 `--single-line`）、`read`、`status`，内部固定使用后台窗口与 JSON 输出，且通过 Node 直接启动 OpenCLI 的 JS 入口，不拼接 shell 命令：

```powershell
node $lock run --token $token -- new
node $lock run --token $token -- send --text-file '完整路径/brief.txt' --single-line
# 此处先留出生成时间，完成独立工作或可中断等待，到预定回读时间后再执行下一条。
node $lock run --token $token -- read
# 同一 token 持续用于后续反馈、等待与读回；完整正文验收并保存后才释放。
node $lock release --token $token
```

`send` 从 UTF-8 文件读取全文并作为单一参数传入。示例中的 `--single-line` 适用于普通自然语言提纲：去掉发送副本开头的 UTF-8 BOM，并将 CRLF、CR、LF 及 Unicode 段行分隔符替换为空格，不修改原文件或合并其他空白。换行具有结构含义时省略该选项，默认发送保持原文。提交成功只代表已发送，不代表正文已生成。不要把 `release` 放在每条命令或每轮返修后；它结束的是整篇稿件对默认豆包会话的占用。对话取消时若正文仍在生成或提交结果未知，先保留锁并说明未决状态，待确认不再需要该会话后再释放。文档格式转换与其他不再访问豆包的工作可在释放后完成。

`node $lock status` 只查看本地锁，不访问豆包，也不显示持有凭证。错误 token 不能运行或释放；网页命令仍在执行时也不能释放。OpenCLI 失败会保留稿件锁，便于原持有者先核对结果再决定是否重试。辅助脚本从 PATH 中查找 OpenCLI 的 npm 安装入口；找不到时，可将 `DOUBAO_PEN_OPENCLI_JS` 设为已安装 OpenCLI 的绝对 JS 入口路径。不要用字符串拼接运行 `.cmd` 或 `.ps1`。

锁没有过期抢占机制：长时间思考、人工核查或暂停均不构成自动解锁的依据。异常终止可能留下 `lease.json` 或 `operation`；先向用户说明 owner、时间及本地锁状态，确认原任务不再运行、浏览器命令已结束且无需继续读回或返修，并获得明确授权后才能清理这两个已确认的残留项。禁止按时间自动删除锁。若写共享锁目录被沙箱限制，申请该目录所需权限，不能改到各对话自己的工作目录。

`DOUBAO_PEN_LOCK_DIR` 仅供测试或管理员为所有调用者统一指定目录。普通写作保持默认值，不能每个对话设一个值。测试用的自定义目录必须与实际豆包会话隔离。

## 输入校验失败

OpenCLI 1.8.6 的 `Failed to insert text into Doubao composer` 出现在发送前：适配器先写输入框，再把读回文本与提示原文比较，只统一 CRLF/LF 和首尾空白。富文本输入框若改变段落换行，文字可能已进入输入框，但严格比较仍会失败，此时该调用尚未执行点击发送。连接成功只能证明页面可达，不能证明输入或发送成功。

已观察到普通多段提纲连续输入校验失败，而只将换行改为空格后成功发送。普通提纲可首轮就用 `--single-line`；不要改写词句、删减内容或覆盖原始提示文件。换行承载语义的内容不能盲目压平；需重新组织为语义完整的普通文本，或报告当前适配限制。

遇到错误时先识别阶段，不把所有失败都说成“文字没有进入输入框”：

- 错误明确为上述发送前输入校验失败，且会话中没有该提示对应的新用户消息时，可持同一锁用单行兼容方式重试一次；不要再次原样提交相同多行输入，不手动补点发送键。
- 超时、断连、验证挑战或已执行发送动作后的异常属于结果未知。按既定间隔等待后读回，核对是否已有对应用户消息或答复；存在则继续读回，不能因 CLI 报错就重复发送。
- 单行兼容也失败或无法确认发送阶段时保留锁，记录错误、输入是否含换行、会话核对结果和未决状态；继续针对性诊断，不高频重试、不在其他对话中借用该锁。

准确报告“输入读回校验失败，尚未确认提交”或有依据的“发送前校验失败，未执行发送”，不要把输入、提交和生成混为一谈。辅助脚本不会自动重发，也不会放宽第三方适配器的比较规则。

## 等待与回读

提交后记录时间，按任务量预留思考与生成时间：普通短文可先等约30—60秒，长文或复杂任务适当延长，再做首次回读。等待期间优先处理文件准备、已有材料整理等必要且不依赖正文的工作，不为填满等待时间扩大检索或审查范围。没有独立工作就使用可中断等待，单次阻塞等待不超过60秒；更长间隔分段等待并保持必要的进度沟通。

到预定时间使用持有的 token 经 `run -- read` 读取一次。若仍在思考、生成或正文明显不完整，再等约30—60秒后查看，耗时较长时拉长间隔；不要每隔几秒查询页面或锁状态，也不向豆包发送“写完了吗”等催问。若正文已完整并有结束迹象，直接拿回继续，不例行连续读取两遍来证明稳定。整个等待期间保留稿件锁。

默认站点会话可接续。等待期间保持原会话，不新建对话、不并行提交其他稿件。发送超时或结果未知，先留出合理时间，再读取确认是否已送达与仍在生成，之后决定是否重试；不要重复提交同一消息。工具只返回 `正在思考`、`已完成思考`、System 超时提示或部分正文，都不算收到完整稿件；思考状态结束不代表正文已被工具读回。读取完整的 Assistant.Text，不把表格预览、旧答复、用户提示或思考内容当成新稿。遇到明确连接错误、登录门禁或长时间无进展时，按具体问题处理，不无限等待或密集重试。

页面转录可能附带 `Image:` 头像链接等界面元数据。保留原始返回，核实后可在交付副本中去掉这些非正文元素；不能据此删改正文句子，也不要下载头像等无关素材。

命令查找失败时，先检查当前机器的 OpenCLI 安装位置和 PATH；Windows 可用 `Get-Command opencli -ErrorAction SilentlyContinue` 查询。除非实际需要，不安装或升级工具、不新增浏览器扩展。
